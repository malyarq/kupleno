# Настройки GitHub

Локальные workflow не защищают репозиторий сами по себе. На 6 августа 2026 года для `malyarq/market-trat` уже включены перечисленные ниже внешние правила.

## `main`

- изменения только через pull request, включая действия администратора;
- обязательный commit status `MarketTrat verification`, который workflow ставит только после тестов, воспроизводимой сборки и загрузки артефакта;
- ветка должна быть актуальна перед merge;
- обязательных чужих approvals нет, поэтому одиночный владелец не заблокирован;
- открытые обсуждения должны быть закрыты;
- force push и удаление ветки запрещены;
- история остаётся линейной.

Первый PR после включения защиты обязан содержать `.github/workflows/verify-release.yml`: именно он создаёт требуемый check. Если имя job меняется, сначала нужно безопасно обновить обязательный context, иначе merge будет заблокирован.

## Теги `v*`

Активный ruleset `Immutable version tags` запрещает изменение и удаление существующих версионных тегов. Создание нового тега разрешено. Кандидат строится только событием push тега; ручного запуска из произвольной ветки нет.

Тег должен быть аннотированным и совпадать с manifest/package/CHANGELOG. Это дополнительно проверяет `npm run verify:release -- vX.Y.Z`.

## Actions

- Actions включены;
- разрешены только GitHub-owned actions;
- полный commit SHA обязателен;
- workflow token по умолчанию получает только явно указанные права;
- релизный workflow имеет только `contents: read`;
- обычный verify дополнительно имеет только `statuses: write`, чтобы после всех шагов поставить защищённый status на проверенный commit; права менять код или публиковать релиз у него нет.

## Security

- Dependabot alerts включены;
- Dependabot security updates включены;
- Private vulnerability reporting включён;
- secret scanning и push protection включены;
- уязвимости принимаются через Security Advisories, а не публичные Issues.

## Проверка после изменения настроек

1. PR без `MarketTrat verification` не сливается.
2. Прямой push в `main` отклоняется.
3. Существующий `v*` нельзя передвинуть или удалить.
4. Security tab принимает приватный vulnerability report.
5. Workflow с action без полного SHA отклоняется.

Внешние правила нужно повторно проверить после передачи репозитория, смены тарифа GitHub, переименования job или добавления нового workflow.
