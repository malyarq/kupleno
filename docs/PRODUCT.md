# Контракт продукта MarketTrat

## Для кого и зачем

MarketTrat нужен человеку, который покупает на Ozon, Wildberries или Яндекс Маркете и хочет без передачи истории покупок наружу понять, сколько и на что он потратил.

Главный результат — понятный локальный отчёт: общая сумма, динамика, категории, крупные траты и деньги к возврату. Пользователь не обязан размечать всю историю или осваивать дополнительные возможности, чтобы получить этот результат.

## Что считается корректным отчётом

1. Один расчёт с магазином учитывается один раз. Аванс и итоговый чек одного заказа не становятся двумя покупками.
2. Сумма разобранных строк совпадает с суммой чека. Доставка, сборы и возвраты не теряются.
3. Неполный сбор явно помечен и не заменяет ранее сохранённый полный отчёт без предупреждения.
4. Неоднозначная категория остаётся предположением. Сила правила не выдаётся за вероятность правильности или подтверждённую ошибку.
5. Ошибка сохранения не оставляет интерфейс в состоянии, которого нет в базе.
6. Резервная копия восстанавливает покупки, профили, правила, бюджеты и настройки.

## Основной путь

1. Установить или обновить расширение.
2. Выбрать магазины и собрать покупки.
3. Сразу увидеть динамику, категории, крупнейшие траты и возвраты.
4. При желании исправить отдельные категории, выгрузить таблицу или сделать резервную копию.

Профили, бюджеты, повторные траты, гарантии и закрытие месяца дополняют этот путь, но не должны его блокировать или скрывать основной отчёт.

## Условие технической готовности

Кандидат готов только когда одновременно выполнены условия:

- полный `npm run verify` и воспроизводимая сборка проходят на точном исходном коде релиза;
- сборка из чистого тега совпадает с опубликованным ZIP;
- после изменения сборщиков пройден авторизованный smoke всех трёх магазинов;
- эталон категорий проходит установленные пороги без уверенно принятых ошибок;
- автоматический браузерный сценарий проверяет основной путь, дополнительные настройки, мобильный вид, сохранение, откат и восстановление;
- нет известной ошибки, которая завышает итог, теряет данные или выдаёт неполный отчёт за полный.

Без авторизованного smoke версия может быть только `code-complete`: корректность текущих страниц и API магазинов ещё не подтверждена.

## Границы текущего этапа

До выполнения критериев выше не добавляются новые возможности, сервер, аккаунты, платежи или облачная синхронизация. Публикация в магазине расширений, подпись, маркетинг и пользовательские исследования не входят в этот этап. Ручная установка и обновление остаются известным внешним барьером.
