# Сопровождение MarketTrat

## Состояния готовности

- `development build` — локальная или CI-сборка из ветки; не релиз.
- `release candidate` — чистый exact commit под аннотированным тегом `vX.Y.Z`, прошедший `verify:release`, включая запуск собранного ZIP в чистом Chromium.
- `published release` — отдельно одобренный кандидат, вручную опубликованный с теми же SHA-256.
- `source-compatible` — автоматические parser fixtures зелёные.
- `live-compatible` — дополнительно пройден авторизованный smoke текущих маркетплейсов.

## Поломка одного маркетплейса

1. Зафиксировать источник, версию, браузер, время и очищенную ошибку.
2. Проверить вход, permissions, лимит/429 и предупреждение о неполной истории.
3. Воспроизвести на минимальной fixture без пользовательских данных.
4. Добавить обезличенный пример в `extension/fixtures/`, чтобы поломка больше не повторилась.
5. Сравнить только владелецкий parser и ближайшие тесты.
6. Исправить parser или временно выдать честное сообщение; не возвращать пустой результат как полный.
7. Прогнать тест источника, полный verify и ручной smoke этого источника.
8. Если затронуты общие storage/security границы, повторить весь release checklist.

При падении одного источника остальные не блокируются. Повтор должен быть доступен отдельно.

## Приоритеты инцидентов

- P0: утечка данных/сессии, удалённый код, потеря или тихая перезапись базы. Сбор и выпуск останавливаются.
- P1: неверная сумма, неполная история без предупреждения, невозможность backup/restore или запуска. Нужен исправляющий релиз.
- P2: отдельный неразобранный чек с явным предупреждением, неточная категория, визуальная проблема без потери действия.

## Выпуск и откат

Полный процесс находится в [RELEASE.md](../RELEASE.md). Код замораживается после документации и review. После исправления замечаний повторно проверяется новый diff, затем собирается exact tag. CI-артефакт ветки нельзя переименовывать в релизный.

Если опубликованный ZIP не совпадает с candidate SHA, релиз удаляется/помечается отозванным и пересобирается новым patch-тегом. Тег и asset не заменяются молча.

## Зависимости

Runtime npm-зависимостей нет. Playwright используется только для проверки и зафиксирован в `package-lock.json`. GitHub Actions закреплены полными commit SHA. PDF.js проверяется локальным hash gate и описан в `THIRD_PARTY_NOTICES.md`. Dependabot ежемесячно проверяет Actions и npm metadata.

## Владение

`@malyarq` владеет release, security, storage, permissions и privacy изменениями. CODEOWNERS фиксирует это в GitHub. Перед передачей проекта новый владелец должен получить доступ к репозиторию, Security Advisories и настройкам branch/tag rulesets.
