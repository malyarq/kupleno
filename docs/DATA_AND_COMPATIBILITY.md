# Данные и формат

## Текущий контракт

Все постоянные идентификаторы принадлежат Куплено: технические ключи начинаются с `kupleno-*`, основная база называется `kupleno-storage-v1`, а резервная копия использует формат `kupleno-backup`. Имена считаются частью публичного формата данных и меняются только вместе с явной миграцией.

| Слой | Значение | Где задано |
|---|---:|---|
| IndexedDB | `kupleno-storage-v1`, версия `1` | `extension/storage.js` |
| Снимок | версия `1` | `extension/storage.js` |
| Backup | формат `kupleno-backup`, версия `1` | `extension/storage.js` |
| Максимум операций | 100 000 | `extension/storage.js` |
| Максимум backup | 64 МиБ | `extension/storage.js` |
| История | 12 снимков | `extension/storage.js` |
| Браузер | Chromium 116+ | `extension/manifest.json` |

Текущая версия читает backup версии 1 и отклоняет неизвестные версии до изменения базы. Это защита от тихого повреждения. Совместимость гарантируется только между опубликованными версиями Куплено.

## Гарантии

Аналитика рассчитана на RUB. Нерублёвые CSV и backup отклоняются до замены данных. Если такая валюта уже есть в старой локальной базе, суммы не показываются как рубли: приложение блокирует изменения и позволяет скачать исходную резервную копию. Исходные строки в базе не удаляются.

Признак непроверенного CSV сохраняется в metadata backup v1. Новый сбор не снимает предупреждение о ранее импортированной части. Для старых смешанных копий, где происхождение уже было потеряно, точно восстановить его автоматически нельзя; копии без сведений о сборе считаются непроверенными.

- Обновление внутри формата backup v1 сохраняет операции, профили, правила, бюджеты, возвраты, гарантии, закрытые месяцы и решения по советам.
- Импорт не меняет текущую базу до полной проверки файла и подтверждённого сохранения.
- Повреждённый, слишком большой или неподдерживаемый backup отклоняется целиком.
- Результат больше 100 000 операций отклоняется до записи во временное хранилище и до замены прежнего отчёта.
- Ошибка записи снимка возвращает интерфейс к последнему действительно сохранённому состоянию.
- Если старый отчёт содержит ранний и итоговый чеки одного заказа Ozon, следующий сбор автоматически становится полным. Ранний чек удаляется только после полного сопоставления его позиций с более поздними итоговыми чеками; неполное совпадение сохраняет обе стороны.
- Версия 0.11.0 и более ранние не обязаны понимать полный backup текущей версии.
- Downgrade безопасен только после экспорта backup и проверки, что старая версия поддерживает его формат.

При открытии сохранённого отчёта автоматические категории строк, собранных из маркетплейсов, пересчитываются текущими правилами. Явные ручные категории и пользовательские правила сохраняются. Для импортированных строк без служебных признаков исправляются только известные ошибки правил. Название `Подписки` отображается как `Цифровые покупки`, а `Пакеты и упаковка` — как `Дом`.

## Правило изменения схемы

Нельзя повышать `DB_VERSION`, `SNAPSHOT_VERSION` или `BACKUP_VERSION` без одного связанного изменения:

1. fixture последней опубликованной версии;
2. явная функция миграции по шагам без пропуска версий;
3. тест `old → new` для операций и всех настроек;
4. тест отказа без частичной записи;
5. описание обратимости и минимальной версии для отката;
6. обновление этого документа, CHANGELOG и release checklist;
7. ручной export → import на чистом профиле браузера.

Минимальная гарантия будущего релиза — читать backup последней опубликованной версии. Если это невозможно, изменение считается breaking и требует major-версии backup, отдельного конвертера и заметного предупреждения до обновления.

## Обновление и откат

### Перед обновлением

1. Откройте `Настройки → Резервная копия` и скачайте JSON.
2. Убедитесь, что файл не пустой и хранится отдельно от папки расширения.
3. Сохраните ZIP и распакованную папку текущей версии до успешной проверки новой.
4. Не загружайте новую папку как второе расширение: изменится ID и локальная база не подхватится.

### Обновление с сохранением ID

1. Распакуйте новый проверенный ZIP во временную папку.
2. Закройте вкладку Куплено.
3. Очистите содержимое уже подключённой папки расширения, не удаляя саму папку.
4. Скопируйте в неё все файлы новой версии.
5. Нажмите `Обновить` на карточке Куплено в `chrome://extensions`.
6. Откройте Куплено, проверьте версию, число операций, профили и последний месяц.
7. Экспортируйте контрольную резервную копию новой версией.

Копирование только поверх старых файлов запрещено: удалённый в новой версии runtime-файл может остаться и создать гибрид двух версий.

### Откат

1. Закройте Куплено.
2. Очистите содержимое той же подключённой папки.
3. Верните полный набор файлов предыдущего проверенного ZIP.
4. Нажмите `Обновить` в `chrome://extensions`.
5. Откройте приложение и проверьте данные.
6. Восстанавливайте backup только если база не открылась и старая версия поддерживает его формат.

Если обновление повысило схему IndexedDB и downgrade не заявлен как совместимый, не экспериментируйте с единственной копией профиля: используйте новый профиль браузера или дождитесь исправляющего релиза.

## Удаление

Кнопка удаления данных очищает основную базу, историю, настройки и временные результаты сбора. Удаление расширения браузером также удаляет его storage. Скачанные CSV/JSON остаются на диске и удаляются пользователем отдельно.
