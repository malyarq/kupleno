# Архитектура MarketTrat

## Назначение

MarketTrat — полностью локальное расширение Manifest V3. Оно получает историю покупок только после действия пользователя, нормализует её, сохраняет в профиле браузера и строит отчёты без серверной части.

## Компоненты

| Компонент | Файлы | Ответственность |
|---|---|---|
| Интерфейс | `app.html`, `app.css`, `app.js` | связывание экранов, пользовательские действия, экспорт, backup и настройки |
| Чистая аналитика | `analytics-core.js`, `analytics-utils.js` | крупные/подробные категории, периоды, даты, суммы и сравнения без DOM |
| Качество отчёта | `report-quality.js`, `source-health.js` | полнота чеков, граница импортированного CSV, диагностика и состояние подключения источника |
| Фоновый процесс | `background.js` | одна задача сбора, восстановление результата после перезапуска MV3 worker, проверка отправителя сообщений |
| Код страницы | `content.js` | запросы только к разрешённым адресам маркетплейса, разбор HTML/PDF и ограничения ответов |
| Категории | `categories.js`, `category-rules.json` | локальная классификация, объяснение решения и консервативная очередь проверки |
| Локальный анализ | `intelligence.js`, `lifecycle.js`, `preferences.js` | повторы, цены, аномалии, возвраты, гарантии, месяцы и пользовательские правила |
| Хранилище | `storage.js` | IndexedDB, снимки, backup, epoch/revision и защита между вкладками |
| Временный результат | `collect-job-store.js`, `collect-result-store.js` | задача в `chrome.storage.session` и готовый результат в IndexedDB до подтверждения сохранения |
| Обновление | `update.js` | сравнение версии с метаданными последнего GitHub Release |

## Поток данных

1. Пользователь выбирает магазины и запускает сбор.
2. Интерфейс запрашивает только необходимые optional permissions.
3. Фоновый процесс проверяет, что сообщение пришло от страницы самого расширения.
4. Код сбора обращается только к allowlist адресов выбранного маркетплейса, с ограничениями времени и размера ответа.
5. Чеки одного заказа сверяются по идентификатору, составу, сумме и порядку расчёта. Неопределённый ранний чек исключается только при полном покрытии более поздними итоговыми чеками.
6. Готовый результат сначала сохраняется отдельно и удаляется только после подтверждённого сохранения основной базы.
7. Основная база создаёт новый снимок; предыдущие данные не заменяются неполным результатом молча.
8. Аналитика, категории, экспорт и советы работают локально.

## Границы доверия

- Сайты маркетплейсов считаются внешними и потенциально меняющимися.
- HTML, JSON, PDF, CSV и backup считаются недоверенным вводом и проверяются по размеру, форме и допустимым полям.
- Другие сайты и расширения не могут вызывать внутренние команды: external messaging не объявлен, sender проверяется.
- `cookies` и host permissions не постоянные; они выдаются пользователем выбранным источникам.
- В расширении нет `eval`, удалённого кода, сервера, аккаунта MarketTrat и телеметрии.
- Extension pages используют CSP `script-src 'self'; object-src 'self'`.

## Надёжность

- максимум 100 000 операций;
- лимит проверяется в сборщике каждого источника, при объединении источников и до записи временного результата;
- до 12 локальных снимков;
- готовый, но ещё не подтверждённый результат хранится до 72 часов;
- epoch не даёт старой вкладке вернуть данные после удаления;
- revision не даёт двум вкладкам молча перезаписать последний снимок;
- ошибка сохранения откатывает интерфейс к последнему подтверждённому снимку;
- все массовые действия и backup проходят нормализацию и валидацию.
- крупные расчёты вынесены из DOM-слоя и имеют отдельный бюджет производительности.

## Проверяемые границы

- эталон `category-benchmark.json` измеряет не только покрытие категорий, но и безопасность неоднозначных названий: сомнение не превращается в уверенную аналитику;
- `browser-smoke.js` запускает собранный ZIP как настоящее MV3-расширение в чистом Chromium;
- библиотека обезличенных повреждённых чеков в `extension/fixtures/` проверяет полный чек, возврат, несовпадение суммы, отсутствие итога и пустой ответ каждого источника;
- `performance-benchmark.js` проверяет чистую аналитику на 100 000 строк и 10 000 уникальных названий;
- Playwright и npm-пакеты используются только при разработке и не входят в runtime allowlist ZIP;
- CodeQL проверяет JavaScript после push в `main`, по расписанию и вручную;
- живые страницы маркетплейсов остаются внешним изменяемым контрактом и проверяются отдельно на авторизованном тестовом профиле.

## Что намеренно отсутствует

Серверная синхронизация, платёжный слой, внешняя аналитика, удалённая классификация и постоянные разрешения. Добавление любой из этих подсистем требует отдельного решения и обновления threat model, privacy и backup-контракта.
