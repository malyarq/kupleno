# Архитектура MarketTrat

## Назначение

MarketTrat — полностью локальное расширение Manifest V3. Оно получает историю покупок только после действия пользователя, нормализует её, сохраняет в профиле браузера и строит отчёты без серверной части.

## Компоненты

| Компонент | Файлы | Ответственность |
|---|---|---|
| Интерфейс | `app.html`, `app.css`, `app.js` | первый запуск, сбор, проверка, отчёты, экспорт, backup и настройки |
| Фоновый процесс | `background.js` | одна задача сбора, восстановление результата после перезапуска MV3 worker, проверка отправителя сообщений |
| Код страницы | `content.js` | запросы только к разрешённым адресам маркетплейса, разбор HTML/PDF и ограничения ответов |
| Категории | `categories.js`, `category-rules.json` | локальная классификация и объяснение решения |
| Локальный анализ | `intelligence.js`, `lifecycle.js`, `preferences.js` | повторы, цены, аномалии, возвраты, гарантии, месяцы и пользовательские правила |
| Хранилище | `storage.js` | IndexedDB, снимки, backup, epoch/revision и защита между вкладками |
| Временный результат | `collect-job-store.js`, `collect-result-store.js` | задача в `chrome.storage.session` и готовый результат в IndexedDB до подтверждения сохранения |
| Обновление | `update.js` | сравнение версии с метаданными последнего GitHub Release |

## Поток данных

1. Пользователь выбирает магазины и запускает сбор.
2. Интерфейс запрашивает только необходимые optional permissions.
3. Фоновый процесс проверяет, что сообщение пришло от страницы самого расширения.
4. Код сбора обращается только к allowlist адресов выбранного маркетплейса, с ограничениями времени и размера ответа.
5. Готовый результат сначала сохраняется отдельно и удаляется только после подтверждённого сохранения основной базы.
6. Основная база создаёт новый снимок; предыдущие данные не заменяются неполным результатом молча.
7. Аналитика, категории, экспорт и советы работают локально.

## Границы доверия

- Сайты маркетплейсов считаются внешними и потенциально меняющимися.
- HTML, JSON, PDF, CSV и backup считаются недоверенным вводом и проверяются по размеру, форме и допустимым полям.
- Другие сайты и расширения не могут вызывать внутренние команды: external messaging не объявлен, sender проверяется.
- `cookies` и host permissions не постоянные; они выдаются пользователем выбранным источникам.
- В расширении нет `eval`, удалённого кода, сервера, аккаунта MarketTrat и телеметрии.
- Extension pages используют CSP `script-src 'self'; object-src 'self'`.

## Надёжность

- максимум 100 000 операций;
- до 12 локальных снимков;
- готовый, но ещё не подтверждённый результат хранится до 72 часов;
- epoch не даёт старой вкладке вернуть данные после удаления;
- revision не даёт двум вкладкам молча перезаписать последний снимок;
- все массовые действия и backup проходят нормализацию и валидацию.

## Что намеренно отсутствует

Серверная синхронизация, платёжный слой, внешняя аналитика, удалённая классификация, автоматическая публикация релиза и постоянные разрешения. Добавление любой из этих подсистем требует отдельного решения и обновления threat model, privacy и backup-контракта.
