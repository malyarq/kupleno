# Как вносить изменения в MarketTrat

## Локальный запуск

Нужны Git, Node.js из `.nvmrc`, `zip`, `unzip` и `shasum`.

```sh
npm ci
npx playwright install chromium
npm run verify
npm run verify:reproducible
```

Зависимостей npm у runtime нет. Playwright — только зафиксированный инструмент проверки интерфейса. Расширение загружается в Chromium через `chrome://extensions → Режим разработчика → Загрузить распакованное расширение` из папки `extension`.

## Правила изменения

- Не добавляйте удалённый код, телеметрию, постоянные host-разрешения или обязательный доступ к cookie.
- Не используйте в тестах реальные чеки, заказы, токены и резервные копии.
- Изменение парсера маркетплейса сопровождайте fixture-тестом и понятным предупреждением для неполного результата.
- Изменение storage, snapshot или backup сопровождайте миграцией, старой fixture и тестом отката по [контракту данных](docs/DATA_AND_COMPATIBILITY.md).
- Изменение разрешений синхронизируйте с `PRIVACY.md`, `README.md` и `extension/manifest.test.js`.
- Изменение пользовательского сценария проверяйте в браузере на обычной и узкой ширине. Если видимые экраны изменились, обновите снимки README из прошедшего exact ZIP по [инструкции](docs/TESTING.md#обновление-снимков-readme).
- Изменение категорий сопровождайте примером в `extension/category-benchmark.json`; опасная неоднозначность должна оставаться на ручную проверку.
- Версии в `manifest.json`, `package.json`, README и CHANGELOG должны совпадать.

## Перед прямым push в `main`

1. Выполните `npm run verify`.
2. Выполните `npm run verify:reproducible`.
3. Проверьте `git diff --check`.
4. Убедитесь, что в diff нет ZIP, пользовательских данных и секретов.
5. Зафиксируйте в сообщении коммита один законченный результат.
6. Отправляйте только линейное продолжение актуального `main`; force push запрещён.

Обычная CI-сборка не является релизом. Релизный кандидат создаётся только из аннотированного тега по [RELEASE.md](RELEASE.md).
